| **2** | **PaintedPoints node** | ⚠️ (Partial/Major) | <ul><li>All required plugs exist (`surfaceMode`, `paintThroughMode`, `relaxObjective`, `targetFilter`, `cachePath`, `cacheMode`, `projectRoot`, `lockMode`, `backupEnabled`, `backupPolicy`, `compactionMode`, `globalModePrecedence`).</li><li>`layers` and `selectionSets` are `StringVectorDataPlugs` instead of the “opaque author‑data‑plug” described in the spec.  This may still satisfy the schema but is a structural difference.</li><li>All node‑level actions (`migrateCacheMode`, `relinkCache`, `upgradeCache`, `validateCache`, `validateAttachments`, `compactCache`, `exportAuthoredCache`, `exportEvaluatedPoints`, `freezeBakeSelection`, etc.) are bound.</li></ul>

| **12** | **Tablet & pressure handling** | ⚠️ (Partial) | The node exposes `pressureDefaults` and `brushDefaults` (size, density, softness, spacing, rotationMode, scaleJitter, widthJitter).  Pressure mapping mode (`PRESSURE_MAPPING_DIRECT` / `CURVE`) is defined but the mapping curve is not wired into the point‑generation logic in the code as seen.  This means the UI will allow selecting direct/curve mode, but the backend likely still applies the default pressure values, so this mapping feature is only partially implemented. |
| **13** | **Randomisation (normal spin, tangent‑frame rotation, width jitter, etc.)** | ⚠️ (Partial) | `rotationMode`, `scaleJitter` and `widthJitter` are exposed in the node, however the actual sampling of random values is not visible in the Python layer.  The C++ core may handle this, but code‑side confirmation is missing. |
| **14** | **Attachment contracts (barycentric, rest‑space, fallback, “anchor mode”)** | ✅ | The `AttachedPoints` node implements barycentric resolution, rest‑space attachment, support for “fallback” anchors and records both valid and fallback points, matching the spec. |
| **15** | **Layer/frame timing (persistent, additive, override)** | ⚪ (Partial) | In `PaintedPoints` each layer/stone includes a `timeMode`, `frameStart`, and `frameEnd` that are interpreted during evaluation.  The node handles persistent + additive semantics.  The “override” policy (manual ordering) is implemented via `globalModePrecedence` and the per‑stroke/layer precedence logic.  The spec’s wording matches the behaviour, but an explicit “override whole node output” node is not exposed as a separate API; it’s integrated.  Therefore this is considered *partial* compliance. |
| **16** | **Other miscellaneous spec items** | ⚠️ (Partial) | • Model‑'Patch' support (e.g. UV/barycentric data) is present, but there is no explicit “fallback to UV” contract beyond `restUV`. <br>• The laser‑based “diagnostics report” file path (`validationCategories`, `validationSummary`) is implemented, but the PDF or human‑readable report generation is not present in this repo. |

Minor contractual differences (layers/selection plug types, pressure mapping, override UI, detailed randomisation) exist but do not severely break functional expectations.
